Experiments & results

Measured engineering outcomes, not agent claims. The current manager has not outperformed a single Codex worker.

The manager has not outperformed a single Codex worker in the recorded live trials. These are small trials, not statistical or production-wide evidence.

Live workers used GPT-5.3-Codex, medium reasoning. Each pair received the same initial source, executable criteria and 420s cap. Tasks covered deduplication complexity/order, bounded retries/permanent errors, and batching with duplicate/missing keys.

v2: Both arms could read the unchanged callback contracts in system.md. Manager completed deduplication and batching through accepted research, authorized code, independent checks and audit. Retry stopped because evaluation demanded more edge-case evidence. No application exception, false completion claim or recorded human intervention occurred. Full v2 record.

v1: Manager completed deduplication; it paused retries and batching over callback contracts. No application exception, false completion claim or recorded intervention. Full v1 record.

Unfinished tasks stay in denominators. Fixture/tool/model changes confound cross-profile comparisons. Token totals mix models and may include cached input; they are not dollar costs. Baseline internal research/corrections and comparative live recovery rates remain unknown. Failed diagnostic profiles are retained separately, never pooled into clean runs.

Bugs found during live trials

Fixed API-key routing, SDK/SQLite thread affinity, invalid-scope crashes, hidden read limits, unhandled manager turn exhaustion, prefetch budget starvation, missing report/check context, premature code-goal completion and mutable/unstarted-worktree scoring. Diagnostic trial 4 was partial after a scoring crash, not a fabricated zero. Trial 1 included a recorded policy intervention. Raw artifacts: .omnitrix/live-api-trial-*.

Separately, real interaction returned a manager reply in 2.52s during a delayed worker, then delivered policy steering/interruption and restored conversation/pending messages. That is a functional check, not a recovery-rate experiment.

Reproduce harness checks

python scripts/demo.py --output .omnitrix/demo-new
python scripts/faults.py --output .omnitrix/faults-new
python scripts/benchmark.py --output .omnitrix/benchmark-new

Mock decisions/coding use actual SQLite, Git and subprocess checks. The demo includes one failed complexity check followed by repair. Nine faults cover worker kill, manager SIGKILL, requirement change/stale result, repeated verification failure, misleading research, lost message/Git acknowledgment, external waiting, and activity without meaningful progress. Fault output includes JUnit/JSON and preserves pytest's exit status.

The benchmark stores initial tree identities, exact candidates, criterion logs, goal/DB IDs, time, usage, repeated queries, repairs and completion checks. Missing measurements are null. Quality means declared criterion coverage; broader business utility is unmeasured.

Multi-hour live comparison

Requires secure OPENAI_API_KEY, writable sessions, Git, installed dependencies and an isolated development machine. Model calls are paid. This authorizes changes only in generated fixtures, never deployment, merge or push. 

export OMNITRIX_MODEL=gpt-4.1
python scripts/benchmark.py --live --allow-code-modifications \
  --hours 4 --steps 12 --arm-seconds 1200 --output .omnitrix/live-4h
  • Use identical fixture/oracle, worker model/runtime and per-arm deadlines. Include all manager/research costs. Arm order alternates to reduce warm-up bias.
  • Manager is model-driven; no mock plan. Authorization follows accepted research.
  • Hours repeats whole trials and may overrun to finish the last one. Scoring is separate and uses immutable candidate revisions, never mutable worker files.
  • Reuse completed arms; inspect incomplete native turns/journals before resuming. No blind replay.
  • Keep steerable via omnitrix --db PATH status/send/messages; record every intervention.
  • Successful calls report usage; count native cumulative usage once per thread. Interrupted calls can omit it. Do not compare costs without checking completeness.
  • An SDK turn ending is not a success claim. Compare explicit claims to executable criteria.

No multi-hour experiment has been performed. Next: larger multi-service tasks, held-out oracles, randomized repeats/uncertainty intervals, equal-resolution baseline telemetry, and live interruption/requirement-change faults. Add infrastructure only after measured need.
