Experiments & results

Measured engineering outcomes, not agent claims. The current manager has not outperformed a single Codex worker.

Measured results

GPT-5.4 coordinated research/evaluation; GPT-5.3-Codex workers used medium reasoning. Each pair received identical initial trees, unchanged executable criteria and a 420s cap. Both arms recorded zero incorrect completion claims.

No measured architecture advantage. The manager completed deduplication and batching. Its retry hypothesis combined a real timeout defect with permanent-error behavior that already worked; after independent falsification, it paused instead of narrowing the investigation.

The full report retains the initial/final trials, exact candidates and the separate focused-retry follow-up. The separate retry follow-up scored Codex 2/2 in 11.600s versus manager 0/2 in 26.003s: it paused after discovery because it incorrectly treated missing code authorization as blocking focused research. That follow-up is not pooled into this three-task aggregate. Machine-readable record.

Development cases were reused during tuning. Manager usage completeness was not certified for the task without a native worker. Tokens mix models and cached input; they are not dollar costs. Unfinished tasks remain in denominators. No statistical, multi-hour or production benefit is established.

Earlier profiles remain available: v2: manager 4/6 in 176.2s vs Codex 6/6 in 59.0s; v1: manager 3/6 in 112.4s vs Codex 6/6 in 62.6s. Fixture, model and tool changes prevent treating these as a controlled trend.

Bugs found during live trials

Live runs exposed API-key routing, SDK/SQLite thread affinity, invalid scopes, hidden read limits, unhandled turn exhaustion, missing report/check context, prefetch budget starvation and mutable/unstarted-worktree scoring. Failures and partial trials are retained.

A separate real Codex repository review found a stale-publication race. A second SQLite connection reproduced it; discovery maps and findings now publish under a writer transaction with a final revision fence. This independent repository review is not a manager benchmark success.

Real interaction also returned a manager reply in 2.52s during a delayed worker, delivered policy steering/interruption and restored conversations/messages. These functional checks do not measure recovery rates.

Mock decisions use real SQLite, Git and subprocess checks. Nine fault scenarios cover process kills, requirement changes, stale results, repeated verification failure, misleading evidence, lost acknowledgments, external waiting and activity without progress. Browser checks require Playwright/Chromium.

Benchmark artifacts retain initial trees, exact candidate revisions, criterion logs, usage, corrections, queries and interventions. Missing measurements remain null. Declared criterion coverage does not measure broader business utility.

Multi-hour live comparison

Requires OPENAI_API_KEY, installed Codex dependencies and an isolated development machine. Calls are paid; code authorization applies only to generated fixtures.

export OMNITRIX_MODEL=gpt-5.4
python scripts/benchmark.py --live --allow-code-modifications \
  --hours 4 --steps 12 --arm-seconds 1200 --output .omnitrix/live-4h
  1. Keep fixtures, oracles, worker models and per-arm deadlines identical. Include manager/research usage and all unfinished tasks.
  2. Score immutable candidate revisions. Reconcile incomplete turns and external actions before resuming.
  3. Use omnitrix --db PATH status/send/messages to steer; record every intervention. Hours repeat whole trials and may overrun to finish a pair.
  4. Check usage completeness and distinguish an explicit completion claim from a turn simply ending.

No multi-hour comparative experiment has been completed. Next evidence should use held-out tasks, repeated trials and live interruption faults. Research quality reports and the Kafka investigation provide separate real-project exploration records.
