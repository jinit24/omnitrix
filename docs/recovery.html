Recovery & operations

An unknown outcome is a reconciliation problem. Inspect what happened before retrying.

One manager owns each SQLite DB. Other processes may inspect state or queue commands. 

omnitrix run GOAL_ID --steps 50 --hours 4
omnitrix status GOAL_ID
omnitrix messages GOAL_ID
omnitrix send GOAL_ID 'What are you working on?' --id unique-id

Preserve state

Back up the WAL-consistent DB, adjacent .sessions.db, instructions, Codex home, repositories/Git metadata, worktrees and artifacts together. Use SQLite backup or stop writes before copying. Copying only the main DB during WAL writes is unsafe. Preserve paths or repair linked worktrees after relocation. Credentials and processes must be reestablished; filesystem restoration does not restore them.

Reconcile before retrying

Normal shutdown interrupts work and retains paused/uncertain state. SIGKILL cannot clean up. Restart marks running work and in-flight sends uncertain; budgets and evidence survive. Ownership uses an OS lock, not a stale PID.

Situation Action
Unknown worker outcome /reconcile TASK_ID; inspect exact native thread/turn
Completed code, lost response Verify the retained candidate without coding again
Known interrupted/failed turn Authorize a bounded repair after reconciliation
Missing native history Inspect artifacts manually; do not blindly replace work
Lost delivery acknowledgment /resolve MESSAGE_ID delivered EVIDENCE or not_delivered EVIDENCE
Old question after reconnect Resume with the actual answer; never reuse an old numeric RPC ID

A missing response does not prove an action failed. not_delivered permits a later explicit resend; it does not resend automatically. Native answers remain sent_no_ack. Exactly-once execution is not promised. SDK research restarts bounded attempts with prior knowledge; pause is interrupt/resume, not an OS freeze.

Changes and stalls

Explicitly accepted policy/goal changes fence affected tasks and revoke code authorizations. Keep original mandatory criteria; reauthorize and verify current requirements. Unaffected work and historical evidence remain.

Distinct observations, command/file outcomes and verification artifacts count as progress. Tokens, repeated identical events and process activity do not reset timers. Waiting does not poll models, but wall deadlines still apply. Research/repair budgets persist; exhaustion escalates. Inspect activity, messages, research runs/queries, external actions and audits.

Nested sandbox limitation

Codex requires its real owner-only /tmp/codex-daemon-<uid> directory. An outer sandbox may mask it with mode 000, preventing nested commands. Use the environment-approved route outside that outer sandbox while retaining Codex's own sandbox. Never disable sandboxing or weaken the reserved directory. Recorded live runs required that route.
