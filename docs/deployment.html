OPERATIONS

One host. Persistent control.

Linux services, password login and HTTPS. SQLite and worker sessions stay on the host.

Prepared, not deployed. A host and DNS name are still required. These commands describe installation; no host configuration has been changed.

Prepare the host

Use a supported Linux host with systemd, Python 3.11+, Node, Git and Caddy. Point your domain at it and allow inbound TCP 80/443. Keep port 8765 on loopback.

sudo useradd --system --home-dir /var/lib/omnitrix --shell /usr/sbin/nologin omnitrix
sudo git clone https://github.com/jinit24/omnitrix.git /opt/omnitrix
sudo python3 -m venv /opt/omnitrix/.venv
sudo /opt/omnitrix/.venv/bin/pip install -e /opt/omnitrix
sudo npm --prefix /opt/omnitrix ci
sudo install -d -o omnitrix -g omnitrix -m 0700 /var/lib/omnitrix/{auth,workspaces,codex}
sudo install -m 0600 /opt/omnitrix/deploy/omnitrix.env.example /etc/omnitrix.env
sudoedit /etc/omnitrix.env

Set OPENAI_API_KEY in that root-readable environment file. Paths may be configured there; writable state must remain under /var/lib/omnitrix unless the service's ReadWritePaths is updated too. Source code and dependencies remain outside worker workspaces.

Create a login and configure HTTPS

sudo -u omnitrix /opt/omnitrix/.venv/bin/python -m omnitrix.cli dashboard-user operator --users /var/lib/omnitrix/auth/users.json
sudo install -m 0644 /opt/omnitrix/deploy/Caddyfile /etc/caddy/Caddyfile
sudo install -d /etc/systemd/system/caddy.service.d
sudo install -m 0644 /opt/omnitrix/deploy/caddy.service.d/omnitrix.conf /etc/systemd/system/caddy.service.d/omnitrix.conf
sudo install -m 0600 /opt/omnitrix/deploy/caddy.env.example /etc/caddy/omnitrix.env
sudoedit /etc/caddy/omnitrix.env

Set OMNITRIX_DOMAIN to your DNS name without a scheme or path. The proxy receives only this domain setting; the dashboard service removes provider credentials from its environment. Reuse an existing Caddy configuration instead of overwriting it when the host serves other sites.

Validate and start

cd /opt/omnitrix
./deploy/check.sh
sudo install -m 0644 deploy/omnitrix-dashboard.service deploy/omnitrix-manager@.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo sh -c '. /etc/caddy/omnitrix.env; export OMNITRIX_DOMAIN; caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile'
sudo systemctl enable --now omnitrix-dashboard
sudo systemctl restart caddy

Open your HTTPS domain and sign in. Create a goal whose workspace is an existing directory under the configured root. A code goal requires a committed Git repository root. Creating a goal does not authorize code changes or start a manager.

sudo systemctl enable --now omnitrix-manager@GOAL_ID
sudo journalctl -u omnitrix-dashboard -u omnitrix-manager@GOAL_ID -f

Replace GOAL_ID with the created ID. Run only one manager service for this database. An exclusive lock rejects a second owner. The manager starts in standby with zero decisions; use the dashboard's bounded Continue control when ready.

Restart and restore

EventBehavior
Process failuresystemd restarts it after five seconds; repeated startup failures stop after three attempts.
Manager restartStarts in standby. Running work and ambiguous sends require reconciliation before another autonomous action.
Service shutdownSIGINT allows manager cleanup; systemd terminates remaining processes after 45 seconds.
Disk persistenceRetains state DB, adjacent conversation DB, worktrees, artifacts, auth sessions and Codex home.

Back up /var/lib/omnitrix, the environment files and source revisions. Stop both application services for a consistent full-directory backup; copying an active SQLite file without its WAL is insufficient. Follow recovery before replacing uncertain work. No template merges code or deploys applications.

Validated here: systemd unit syntax, CLI flags, and Caddy 2.11.7 configuration. The official Caddy download matched its published SHA-512 checksum. A local HTTPS test verified secure login, CSRF-protected goal creation and logout using a temporary CA trusted only by the test client:

.venv/bin/python deploy/check_https.py --caddy /path/to/verified/caddy

Public DNS, certificate issuance, host-specific Codex sandbox execution and restart recovery still need validation on the selected host. No public deployment is claimed.
