Architecture

One conversational manager. Bounded specialists. Durable evidence. Explicit authorization.

Corrective loops are bounded. Insufficient evidence returns targeted research feedback. A local test failure returns repair feedback. Incorrect assumptions return to research. Exhausted budgets escalate to the manager.

Context and control

SQLiteSession('manager:<goal-id>') retains manager conversation in the adjacent sessions DB. The latest 12 session items and task summaries bound prompt context; worker histories remain separate. Goals, original criteria, decisions and knowledge survive restarts.

A process lock enforces one owner per database. An async actor lock serializes decisions; durable inbox messages reach that owner without starting another. Waiting dependencies do not poll a model. Deadlines and reasoning budgets pause work.

Policy and requirement changes require explicit acceptance. Review shows old/new instructions, added criteria, affected tasks and approval/evidence effects. Each proposal binds its original goal/policy revisions; stale proposals cannot apply. Mandatory originals remain. Task generations reject affected late results, while unaffected work remains available.

Research and knowledge

StageBounded contract
DiscoveryAt most 20 explicit sources; map resources and rank opportunities.
Focused researchAt most 8 sources; one falsifiable hypothesis, contradictory evidence and an execution budget.
EvaluationInspect captured evidence independently; support, falsify, request targeted evidence or block.
ManagerResolve the highest-value uncertainty; retry with feedback, replan or stop.

Research reads scoped local UTF-8 exports: 32 MiB per file, 1–100 lines per call. Knowledge prefetch preserves discretionary read budget. DB-backed SDK tools are async. Reports return directly to the manager.

Evidence records excerpts, source hashes and timestamps. Citation gates reject missing or stale citations; an LLM cannot establish truth by assertion. Independently supported claims become verified. Discovery maps and findings publish atomically with a final goal/policy revision check under a SQLite writer lock.

Exact question/scope/source signatures detect repeat investigations. Changed sources and aged logs/metrics flag stale knowledge. Time, tool, turn and attempt caps persist; exhausted budgets escalate. These mechanisms do not detect every paraphrase or guarantee good research judgment.

Coding and verification

  1. User authorization binds accepted research, goal/policy revisions, allowed paths, checks and attempt limits. Every mandatory criterion needs an executable check.
  2. Real Codex edits an isolated worktree. Candidate SHA, artifacts, concerns and questions persist. No automatic merge or deployment follows.
  3. Independent subprocesses execute authorized checks in a clean worktree at that exact candidate. Outputs, digests, exit codes and revision coverage persist.
  4. Local defects receive bounded repair. Incorrect assumptions return to research; repeated failures require a changed approach.
  5. A goal audit compares the candidate against every current criterion. A worker success claim cannot complete a code goal.

The UI checklist requires current authorization, goal/policy revisions and candidate SHA. One passing assertion cannot hide another failing check for that criterion; whole-goal verification requires one implementation covering all criteria. Trusted test commands are not a hostile-code sandbox.

Codex and delivery

OPENAI_API_KEY configures the Responses provider through env_key; its value is never persisted by the adapters. Session IDs and a writable Codex home survive application restarts.

Native thread start/resume/read and turn start/steer/interrupt APIs preserve real runtime identity. Steering uses expected-turn preconditions. Old connection-specific question IDs cannot be replayed after reconnect.

Delivery distinguishes pending, sending, acknowledged, uncertain and sent_no_ack. RPC acceptance does not establish task completion. Unknown outcomes require reconciliation before retry; SDK research restarts as a fresh bounded attempt.

Recovery and observation

A separate heartbeat continues during slow manager replies. Online requires both a held owner lock and a recent heartbeat; a held lock with an old heartbeat is stale. Clean shutdown records stopped state. Worker activity and tokens do not count as meaningful progress.

Dashboard snapshots use read-only transactions. Authenticated commands append to the durable inbox. Goal creation validates an existing workspace inside the configured root, preserves original criteria and is idempotent; it neither starts an owner nor authorizes code changes.

Password login uses scrypt hashes, persistent revocable sessions, secure HttpOnly cookies behind HTTPS, origin checks and CSRF tokens for writes. Optional bearer access remains available. The UI separates live, recorded, stale and offline state and retains its last snapshot after connection failures.

Single-host service templates provide persistent paths and an HTTPS proxy. They are tested locally, not publicly deployed. GitHub Pages serves archived experiment snapshots. See recovery for uncertain actions and backups.
