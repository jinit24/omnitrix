Architecture

One conversational manager. Bounded specialists. Durable evidence. Explicit authorization.

Corrective loops are bounded. Insufficient evidence returns targeted research feedback. A local test failure returns repair feedback. Incorrect assumptions return to research. Exhausted budgets escalate to the manager.

Python + OpenAI Agents SDK + SQLite + real Codex workers. One local manager owner; no broker, workflow framework, distributed scheduler, automatic merge or deployment.

Context and control

SQLiteSession('manager:<goal-id>') preserves conversation in the adjacent sessions DB. The latest 12 session items and task summaries bound prompt context. Original criteria, policy, decisions and knowledge remain retrievable; detailed worker histories stay separate. Role instructions live in instructions/ Markdown.

A process lock prevents competing owners; an async actor lock serializes manager calls. SQLite inbox messages allow another CLI process to steer the owner. Waiting questions and external dependencies do not poll an LLM. Reasoning/time exhaustion records a pause.

Permanent changes require explicit proposal acceptance. Policy versions and goal revisions are append-only; original mandatory criteria cannot disappear. Affected task generations reject late results. Unaffected work and old evidence remain. Policy/goal changes revoke implementation authorizations and approvals, requiring reauthorization.

Research and knowledge

Stage Contract
Discovery At most 20 explicit sources; map resources and rank opportunities
Focused research At most 8 sources; one hypothesis, falsification condition and budget
Evaluation Read captured evidence independently; support, reject, request evidence or block
Manager Resolve the highest-value uncertainty; retry with feedback, replan or stop

Research tools read scoped local UTF-8 files/exports only: 32 MiB per file, 1–100 lines per read. No shell, remote collectors or recursive crawl. Knowledge prefetch happens before investigation without consuming a discretionary read. DB-backed SDK tools are async to preserve SQLite thread ownership. Reports go directly to the manager.

Captured evidence includes excerpt, lines, content hash, source modification time and observation time. Citation gates reject invented/stale citations and unsupported claims; LLM evaluation still cannot prove semantic truth. Only independently supported cited claims become verified. Rejected/invalidated findings remain searchable.

Opportunity scores are impact * confidence / (risk * effort), using explained ordinal inputs; unsupported confidence is zero. These are prioritization aids, not economic forecasts. Canonical question/scope/source/revision signatures detect exact repeat investigations, not all paraphrases. Changed/missing sources or observations older than 24h flag staleness. Metric freshness still needs judgment.

Timeouts, tool/turn caps, attempt caps and a persisted goal budget (12 role runs by default, including evaluation) bound work. Three identical invalid plans escalate. Retrying requires targeted feedback and cannot reset budgets.

Coding and verification

  1. User authorization binds accepted research, current goal/policy revisions, allowed paths, checks and attempt limits. Every mandatory criterion needs a check; external oracles are hashed.
  2. Real Codex edits an isolated detached Git worktree with workspace-write sandbox and no sandbox network or automatic escalation. Candidate SHA, handoff, artifacts and concerns persist.
  3. Separate processes run authorized checks in a clean worktree at that exact SHA. Outputs, digests, exit codes and criterion/revision coverage persist. Source/HEAD changes fail verification.
  4. Local defects get bounded repair; incorrect assumptions return to research; repeated failures escalate. Success becomes ready_for_audit.
  5. A manager-requested audit checks current requirements, authorization, candidate and immutable artifacts. Only a passing audit completes implementation. No merge or deployment follows.

Code goals can require verified implementation before any assignment exists. Test commands are trusted local processes with provider credentials removed, not a hostile-code sandbox. Oracle coverage bounds what success establishes; use external isolation for untrusted code.

Codex and delivery

OPENAI_API_KEY selects an explicit Responses provider through env_key, never a persisted key value. Sessions use a writable local Codex home. Without the key, existing auth is preserved.

Native methods: initialize, thread/start, thread/resume, thread/read, turn/start, turn/steer, turn/interrupt, and user-input responses. Persist thread IDs before turns. Steering uses native expected-turn preconditions, not fake conversation entries.

Delivery states distinguish pending, sending, acknowledged, uncertain and sent_no_ack. RPC acceptance does not prove task completion. Old connection-specific question IDs cannot be replayed after restart. SDK research uses cancellation and a fresh bounded attempt, not live steering.

Recovery and observation

WAL SQLite retains ownership, progress, messages, evidence and revision fences. Native turns and journaled Git actions are reconciled before retry; a missing response does not prove failure. Progress counts distinct observations/command outcomes/artifacts, not tokens or repeated activity. Stalls pause work. See recovery.

The dashboard opens read-only/query-only transactions and never takes ownership. It refreshes committed state every five seconds, shows bounded recent records, and retains the last snapshot on errors. HTML guides are maintained directly. See dashboard.
