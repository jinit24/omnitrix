Mission control

Observe the work without changing it. See what is running, why, and what the evidence says. 

omnitrix --db .omnitrix/state.db dashboard
# Trusted remote access only:
omnitrix --db /absolute/path/state.db dashboard --host 0.0.0.0 --port 8765

Default: loopback, port 8765, read-only. Use trusted access or an authenticated proxy. Goals, paths, findings and messages may be sensitive. No API key is required. The manager runs separately.

Authenticated control

Set OMNITRIX_DASHBOARD_TOKEN securely to 32+ random characters, then start:

omnitrix --db .omnitrix/state.db dashboard --allow-control \
  --allowed-origin https://jinit24.github.io
# Separate owner process; wait for UI commands without initial autonomous decisions:
omnitrix --db .omnitrix/state.db run GOAL_ID --steps 0 --hours 4

Choose Connect manager, enter the backend URL and token, then use Manager chat. Supports messages, steering, pause/cancel, bounded decisions, reconciliation and policy/requirement proposals. Review and explicitly accept permanent changes. Code authorization remains in the CLI; no deployment or arbitrary database writes are exposed.

Commands enter the existing durable inbox. A queued receipt is not success: the manager replies and acknowledges separately. Stable request IDs prevent duplicate sends; stale revisions and cross-goal task references are rejected. If no owner is running, commands remain pending.

Enabled control protects state and commands with a bearer token. Browser tokens stay in memory; disconnect or close the tab to clear them. Cross-origin requests require an explicit allowed origin. GitHub Pages needs a reachable HTTPS backend (a trusted TLS proxy in front of this HTTP server). No public backend is provisioned by the static site. Localhost HTTP is supported for local use.

GitHub Pages

Pages shows recorded experiments until you connect an authenticated backend. Enable Settings → Pages → GitHub Actions; the Publish experiment snapshot workflow deploys on changes to main. Build locally with python scripts/build_pages.py. The export omits sessions, local paths and message bodies. No credentials or databases are published.

Data boundaries

  • Read-only/query-only SQLite transaction per request; no ownership, schema creation or writes.
  • Five-second visible-page refresh; failures retain the last snapshot and timestamp.
  • Missing DB stays absent. No fake/sample data or model calls.
  • Latest 200 goals and 200 records per category per goal; use CLI export for full history.
  • Read-only by default; opt-in authenticated commands, allowlisted assets, escaped content and local-only Content Security Policy.

Rebuild HTML docs

pip install -e '.[docs]'
python scripts/build_docs.py
python scripts/build_docs.py --check

HTML ships with the app and needs no external services. Only README remains Markdown. Edit the HTML guides directly; rebuild the bundled site after edits. Machine-consumed role instructions remain Markdown. --check detects generated-page drift.
