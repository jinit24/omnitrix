Status & limitations

What is implemented, what has been verified, and where the system still falls short.

Read the evidence boundary. Deterministic tests, live model experiments and unmeasured production outcomes are reported separately. A verified test is not a universal reliability claim.

Evidence

139 tests passed, 1 opt-in live test skipped; ten browser checks passed. Tests use real SQLite, SDK sessions, Git worktrees and subprocesses with deterministic model decisions. The opt-in Codex test requires live credentials.

  • Browser checks cover login, bounded goal creation, approval review, task evidence, delivery recovery, keyboard use, mobile layout and offline snapshot retention. Local validation also restored a password session and displayed an online manager over saved experiment state.
  • Backend regressions cover independent heartbeat during slow replies, stale proposals, concurrent revision changes, exact candidate coverage, duplicate commands and scoped idempotent goal creation.
  • Systemd templates and official Caddy 2.11.7 configuration validated. Local HTTPS verified secure login, CSRF-protected creation and logout with an explicitly trusted temporary CA.
  • scripts/demo.py demonstrates research → authorization → failed check → repair → audit. scripts/faults.py retains nine recovery/fault scenarios.

Known limits

  • Single trusted host, local filesystem and POSIX locks; no distributed ownership or exactly-once guarantee.
  • Uncertain native outcomes may require manual reconciliation. Restarts start in standby rather than blindly repeating actions.
  • Research uses bounded local sources. Exact repeat detection misses paraphrases; citations and hashes do not prove semantic truth or metric freshness.
  • Over-investigation, compound hypotheses and confusing code authorization with permission to research can hide useful narrower defects. Prompt improvements have not eliminated these failures.
  • Verification covers authorized executable criteria; it is not a hostile-code sandbox or proof of unspecified behavior.
  • Provider usage can be incomplete after failed/interrupted calls. Observed tokens across models and caches are not dollar costs.
  • No public host/domain is configured. Target-host TLS issuance, Codex sandbox execution and recovery still require validation.

Next work

Validate on the selected host. Run repeated held-out project tasks and multi-hour interruption experiments. Reduce unnecessary research without weakening citation, authorization or verification gates.
