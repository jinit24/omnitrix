Status & limitations

What is implemented, what has been verified, and where the system still falls short.

Read the evidence boundary. Deterministic tests, live model experiments and unmeasured production outcomes are reported separately. A verified test is not a universal reliability claim.

Implemented

Area Behavior
Manager Conversational Agents SDK session, durable objective/criteria/policy and decisions
Interaction Nonblocking CLI, durable inbox, explicit instruction acceptance, native Codex steering/questions
Research Bounded discovery → hypothesis → independent evaluation; shared, revision-aware knowledge
Implementation Explicit authorization, isolated Codex worktrees, executable checks, repairs and final audit
Reliability Restart reconciliation, stale-result fences, uncertain delivery, progress deadlines, durable budgets
UI Status/tasks/hierarchy/knowledge/activity with optional authenticated inbox controls; searchable local HTML docs

No deployment, automatic merge, broker or distributed scheduler.

Evidence

Authenticated-control update: 89 tests passed, 1 live test skipped. Browser checks cover connection, message submission, explicit proposal acceptance and disconnection.

UI update: 60 tests passed, 1 live test skipped. Chromium checks passed for desktop/mobile layout, navigation, task filtering, details, docs search and disconnected-state retention. No browser errors.

Before the UI change: 55 deterministic tests passed; 56 with opt-in live Codex. Tests use real SQLite, SDK sessions, Git worktrees, test subprocesses, process kills and cross-process messages with mocked model decisions. These are not live recovery rates.

  • scripts/demo.py: accepted research → authorization → failed check → repair → audit.
  • scripts/faults.py: nine fault scenarios, including stale results, misleading research, process termination, repeated failures and lost acknowledgments.
  • Live: SDK start/resume, native commands, a manager reply in 2.52s during a delayed worker, policy delivery/interruption, conversation/message restoration and turn reconciliation.
  • Live v2: manager completed 2/3 tasks and 4/6 criteria in 176.2s; single Codex completed 3/3 and 6/6 in 59.0s. No false completion claims. No measured architecture advantage.

Experiments separates fixture/model profiles and retained failures. No multi-hour run, statistical superiority, production benefit or new-machine restoration is claimed. Environment publication is separate.

Known limits

  • Single owner, local filesystem, POSIX locks/process groups and source/editable install.
  • Unknown native outcomes can require manual reconciliation; no exactly-once guarantee.
  • Local bounded research exports only; no remote collectors or semantic duplicate detection.
  • Citation integrity does not prove truth; content hashes do not prove metric freshness.
  • Trusted executable oracles determine coverage; verification is not a hostile-code sandbox.
  • Manager over-investigation can block useful work. The retry trial stopped over extra edge-case evidence; its explanation confused evaluator refusal with user authorization.
  • Native APIs are version-sensitive; failed provider calls may omit usage.
  • Dashboard is read-only by default, with opt-in bearer-authenticated inbox control, and bounded to recent state. Status is not liveness; recorded classifications are not live source revalidation.

Next work

Reduce unnecessary research without weakening evidence gates. Then run repeated multi-hour paired trials with held-out oracles and equal-resolution telemetry. Add semantic retrieval, source adapters or infrastructure only when measurements justify them.

API versions

Inspected: openai-agents==0.24.0, @openai/codex-sdk==0.163.0, Codex CLI 0.159.2 App Server schemas. Both Codex paths use OPENAI_API_KEY; no key value is persisted. Nested sandbox execution needs the approved route described in recovery.
