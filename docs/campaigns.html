Durable research campaigns

Campaigns investigate a pinned local Git checkout using bounded discovery, hypothesis testing and fresh independent evaluation. They can remain active for days, with saved limits and an unexplored source catalog. The current Kafka investigation is an experiment; a multi-day reliability result has not been established.

Limits and money

The first invocation requires --days (up to 30), --decisions, --research-runs and --dollars (no greater than 25). Resume the same DB/goal without those flags. Saved deadline, consumed decisions, role attempts and dollar reservations do not reset.

The default manager strategy uses pinned gpt-4.1-2025-04-14. The optional investigator strategy uses gpt-5.3-codex for direct exploration, with fresh GPT-5.3-Codex independent evidence and completion reviews. All use the standard service tier and share one immutable dollar ceiling. Every request retains its actual model price, including after a strategy switch.

Fresh bounded recovery requests have their own reservations. Hosted tools, native Codex workers and unpriced models are excluded. Independent jobs using the same API account are outside this goal's ledger.

Large repositories and evidence

The investigator can search literal content across explicit indexed files with search_scope. Each page bounds filenames, bytes, process time and returned matches, captures actual source evidence and provides continuation. It requires ripgrep. Filename catalog search remains separate; a zero-hit content page is not exhaustive absence proof. Both live comparison arms receive the same navigation tool.

A streamed Git inventory builds a SQLite path catalog, with keyset pagination, component buckets and observed/unexamined counts. Full histories stay on disk; bounded manager state and recall tools prevent replaying the entire investigation. Excerpts and source counts describe observations, not exhaustive repository coverage.

omnitrix --db state.db campaign GOAL_ID --prepare-only \
  --evidence build/observations/context.txt \
  --evidence build/observations/service.log \
  --evidence build/observations/measurements.csv

Evidence paths must be existing UTF-8 files within the goal workspace, at most 32 MiB. Register exports explicitly; they retain a separate origin from tracked Git source. Record provenance, workload, units, measurement window, environment and limitations. Partition larger data. A local unit-test duration does not establish Kafka broker latency or production throughput.

Recovery and stopping

omnitrix --db state.db campaign GOAL_ID
omnitrix --db state.db campaign GOAL_ID --pause
# After diagnosing a deliberate pause or false early completion:
omnitrix --db state.db campaign GOAL_ID --continue-paused
# Optional direct investigation; the original deadline and $25 ceiling survive:
omnitrix --db state.db campaign GOAL_ID --strategy investigator --continue-paused

One owner holds the DB lock. Read-only SDK interruptions retain evidence and charged attempts; uncertain requests keep their cost reservations. Explicit continuation records the previous stop and resets only the stagnation window. Crashes and ordinary resumes preserve it. It does not authorize resetting limits or replaying native actions.

Deadline, decision, role-run and dollar exhaustion stop work. Eight decisions without a new source excerpt or revision pause the owner; rereading or recalling identical evidence does not count as progress. New workers get their bounded chance to read before the stagnation check. Invalid structured outputs and transient connection/timeout/429/500 failures allow at most three fresh planning attempts before pausing; failure counters survive restart. No action is replayed. Raw model output is retained in SQLite before schema parsing. Investigate persistent failures before continuing. The process needs a surviving host or an external process supervisor; no cloud scheduler or machine-to-machine recovery is included.

Default completion minima require 20 observed files, 4 component buckets, 6 independently resolved hypotheses and 2 distinct verified code mechanisms. A mechanism needs a workload, falsification condition, independently assessed avoidable work, an equivalent cheaper alternative, and primary scoped code with an exact observed symbol. Rephrasing the same locator/symbol does not multiply the count. Older weaker proofs need revalidation. Plausible ordinary costs have a separate candidate category; evidence gaps and measurements are also separate. These checks do not prove semantic correctness. Do not invent issues to satisfy them; budget/deadline exhaustion may produce an honest incomplete or negative result.

After three discovery jobs, the manager allocation controller schedules a bounded test of an eligible cited mechanism/measurement lead before another map. Evidence-gap leads are excluded. The investigator selects and studies sources directly, then hands captured observations to a fresh independent reviewer. Each factual finding receives an explicit citation and category review; mechanism approval also names the resource waste and cites observed code. Older unreviewed category labels do not count toward mechanism minima. The hypothesis itself needs test evidence; missing support cannot falsify it. Absence claims require complete cited scope coverage, and literal absence proves only the exact query. One fresh reviewer correction may repair a rejected terminal review without rerunning the research. Genuine scientific insufficiency is retained.

The investigator also requires an independent assessment of the original objective and every indexed requirement against fresh verified finding IDs before completion. Unchanged failed assessments are cached. Numerical minima alone do not establish that the objective was solved. Controlled live comparisons still favour a single Codex-model agent on time and cost; see the complete development comparison history. These reused synthetic workloads are regression tests, and the single-agent arm uses Responses API tools, not native Codex CLI.

Longitudinal tracking

research-quality.html is generated from docs/research-quality.json. Each issue has its original diagnosis, current status, and dated observations, changes, tests and regressions. Experiment summaries keep their earlier timestamped versions. Model outcomes remain separate from deterministic guard tests and manual validation.

Campaign HTML checkpoints are replaced atomically between bounded planning turns, approximately once per minute while the event loop advances, and on exit. A slow planning call can delay the HTML checkpoint; request/evidence records are written to SQLite as work occurs. The SQLite history and exported report include decisions, research queries/evidence, evaluations, inventory queries, challenges, recovery events and a per-request spending ledger. Preserve the DB and any .sessions.db sidecar with their WAL state before moving machines; keep the pinned checkout and exported evidence.
