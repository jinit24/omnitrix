VALIDATION / 2026-10-19

Long-running reliability

Requirement-bound progress and an isolated Django repair experiment.

Outcome

The final profile repaired two deliberately seeded regressions in Django at cae7247962de54a94023d28d84f05fc9842e9646, a checkout with 6,929 tracked files. It passed all three authorized criteria, including 129 unchanged upstream data-structure and HTTP-wrapper tests, then passed the exact-revision goal audit. The final manager used GPT-5.4 and the worker used GPT-5.3-Codex with medium reasoning.

Elapsed time: 217.3 seconds. Candidate: 2bf5d2ccfdbcb8666895529a569ec754987aea4c. The manager was restarted after research acceptance and authorization, before coding; it continued from durable state. The final run received no human steering. Worker commands were bounded; the independent verification process established all authorized acceptance criteria. The preceding profile demonstrated a worker-context timeout followed by successful independent verification.

Local regression suite: 93 passed, 2 skipped. The skipped tests require separately enabled live experiments. The live Django run is reported separately.

Changes

  • Evaluation receives current requirements, constraints and policy. Blocking gaps name their basis and next action; optional uncertainty stays explicit.
  • Manager decisions have four discretionary tool calls. Malformed decisions receive one bounded correction before a durable pause. Recoverable plan errors include known-valid file paths and cannot immediately become an external-input or research pause.
  • Research scope failures are recorded with the existing file paths. The manager must create an expanded explicit plan instead of trying to expand scope through retry prose. The durable total research budget still applies.
  • The latest focused research outcome, feedback, scope gaps and retry eligibility are reconstructed from SQLite every turn. Full reports are available through paginated recall.
  • Code-goal pauses distinguish research prerequisites from missing authorization. Independent verification results and the latest audit are visible in status. A successful current audit atomically completes both the implementation and the goal. Explicit authorization, evidence integrity, independent checks and exact-revision audits remain enforced.
  • Usage is persisted after each completed model response, even if the enclosing run later fails. Workers are instructed to use an OS-enforced command timeout and hand off execution-context limitations to independent verification.
  • The default coordinator and research model is GPT-5.4; OMNITRIX_MODEL still overrides it. GPT-4.1 repeatedly stopped during planning in the earlier profiles.

Testing budget

The authorized ceiling was $25. Recorded responses total approximately $5.58 at standard token rates, charging cached input at the full input rate. Adding a $2 reserve for the first unmetered profile gives $7.58. These figures are estimates, not invoice totals. Each later run used a $3 observed-usage stop threshold to leave substantial headroom for in-flight responses.

Rates per million input/output tokens: GPT-4.1 $2/$8, GPT-5.4 $2.50/$15, GPT-5.3-Codex $1.75/$14. See the source URLs in the machine-readable report. Per-response input sizes stayed below the GPT-5.4 long-context pricing threshold.

Protocol and reproduction

The baseline upstream suite passed before fault injection. The isolated fixture replaced OrderedSet reverse iteration with forward iteration and disabled MultiValueDict.getlist copying. No upstream tests were edited. Independent oracles imported candidate code while running unchanged tests from the separate clean checkout. The permitted edit was only django/utils/datastructures.py. The final patch restores the upstream behavior. Nothing was pushed to Django.

Limits and next work

This is one bounded repair inside a large repository, with seeded defects and a restart between stages. It is not discovery of an upstream bug, a whole-repository audit, a multi-hour trial, a process-kill recovery rate or evidence that a manager beats a single worker. The worker-context test hang was observed; its underlying runtime cause was not established. OS timeouts are requested from the worker and were observed in the final run; they are not a universal tool-execution enforcement layer.

Next: repeated multi-hour trials with matched single-worker baselines, faults during live work, compact milestone state as history grows, and measured recovery from genuinely uncertain external outcomes. Keep unresolved outcomes visible and require reconciliation before replay.
